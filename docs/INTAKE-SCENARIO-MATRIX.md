## Модель состояний (как есть в коде)

Каждый чат = один Durable Object `IntakeBuffer` с двумя состояниями:
- **idle** — всё пишется в `buf`, показывается одна плашка-накопитель с кнопкой «▶️ Запустить». Таймера нет.
- **busy** — идёт прогон: новые сообщения копятся молча, но подтверждаются плашкой «⏳ Принял ещё (N)». Кнопка ▶️ появляется снова только когда прогон закончился. Авто-запуска нет.

Запуск прогона — только явный: кнопка ▶️ ИЛИ голое force-слово (`запускай/запусти/поехали/го/go/run/начинай`).

## 1. Матрица: тип сообщения × что происходит

| Вход | idle | busy | Статус |
|---|---|---|---|
| Текст (обычный) | буферится, плашка «Накапливаю (N)» | held + «Принял ещё (N)» | ✅ покрыто (C1,C2,C5) |
| Force-слово «го/запускай» | немедленный запуск буфера | игнор flush, просто held | ✅ покрыто |
| Reply на сообщение бота | байпас буфера → сразу агенту | байпас → агенту | ✅ покрыто (C4) |
| **Фото** | буферится ✅ но… | held | 🔴 **файл теряется при запуске** |
| **Голосовое / аудио** | буферится ✅ но… | held | 🔴 **не транскрибируется, теряется** |
| **Документ** | буферится ✅ но… | held | 🔴 **файл теряется при запуске** |
| **Видео** | буферится | held | 🟠 буфер принимает, но `handleMessage` не умеет видео |
| Стикер/гео/контакт/опрос | не буферится → «⚠️ не могу обработать» | — | 🟡 реакция есть, но грубая |
| Пустое/сервисное | молча игнор | — | ✅ ок |

### 🔴 ДЫРА №1 — медиа через накопитель доходит до агента строкой-тегом, а не файлом
`IntakeBuffer._dispatch` собирает буфер в **одну строку** и кладёт её в `msg.text`
(`coalesceItem` → `"photo:<file_id>"` / `"voice:<file_id>"` / `"document:<name>"`).
Дальше `handleMessage` первым делом проверяет `if (text)` → уходит в текстовую ветку и
**никогда не скачивает файл**. Итог: агент получает литерал `photo:AgAC123`, а не картинку.
Голос — литерал `voice:...`, транскрипции нет.
Так как `INTAKE_DEBOUNCE` в проде ON по умолчанию, **через накопитель идёт ВСЁ медиа** →
это не крайний случай, а основной путь. Прямое медиа (при debounce off / reply) скачивается
нормально — поэтому баг и не замечали в юнитах.
**Доказано:** `tests/intake-media-content.test.js` — control (прямое фото) зелёный,
буферный shape красный (`fileBase64 = null`).
**Развилка для фикса (нужно твоё решение):** буфер сейчас физически несёт ОДНУ base-msg +
склеенный текст, поэтому не может пронести несколько файлов за один запуск. Варианты:
(A) буфер хранит байты каждого файла и `_dispatch` передаёт агенту массив файлов (честно, но
меняет контракт `runTask`); (B) скачивать/транскрибировать в момент буферизации на шлюзе и
складывать текст+вложения; (C) на первую итерацию — поддержать один файл + подпись, много
файлов за раз запретить. **Рекомендую (B)**: голос транскрибируем сразу (юзер видит текст
как сейчас в прямом пути), файлы качаем при append — тогда `_dispatch` отдаёт настоящий
контент, а не тег. Скажи направление — доведу.

## 2. Матрица: состояние сессии × жизненный цикл

| Сценарий | Ожидаемая реакция | Статус |
|---|---|---|
| Новый диалог, 0 проектов | авто «Основной» | ✅ покрыто |
| Новый диалог, 1 проект | авто | ✅ покрыто |
| Новый диалог, ≥2 проекта | пикер проектов (`pp:<idx>`) | ✅ предикат покрыт, UX-пикер — нет |
| Продолжение (<2ч) | тихо продолжить last session | ✅ покрыто |
| Старая сессия, ≥2 кандидата | Haiku-классификация → авто или пикер | 🟡 путь есть, пикер disambiguation не тестирован |
| /stop → есть задача | «🛑 Остановлена» | ✅ |
| /stop → нет задачи | «🤷 Нет активных» | ✅ |
| Стоп, затем новый запуск | held-сообщения всплывают кнопкой после конца | ✅ покрыто (C5) |
| Новый диалог + файл | пикер пропускается (файл не переприкрепить) | 🟡 см. дыру №9 |

### 🟡 ДЫРА №9 — новый диалог с файлом: файл теряется И всё равно спрашивает проект
Файл идёт в буфер, при запуске `_dispatch` строит msg без `opts.fileBase64` →
в `handleMessage` `hasFile === false` → показывается пикер проекта (хотя логика №517 хотела
его пропустить для файлов), а сам файл уже потерян (дыра №1). Двойной сбой на одном пути.

`index.js` на `new_chat_members`/`left_chat_member` делает только `SESSIONS.delete(mc:...)` и
`return`. Когда добавляют **самого бота** — нет ни приветствия, ни инструкции «войдите /login,
это 1-на-1 воркфлоу». Юзер явно называл этот сценарий («добавление в группу») как требующий
«стандартной грамотной реакции». Сейчас — тишина.

## 4. Нестандартные апдейты и кнопки

| Сценарий | Что сейчас | Статус |

## 5. Главный концептуальный разрыв: разговор vs накопление

В idle-состоянии **любой** текст буферится — отдельного разговорного пути в idle НЕТ.
Единственный способ получить прямой ответ (не накопление) — **reply на сообщение бота**
(`shouldDebounce` → `msg.reply_to_message` → байпас). То есть свежий вопрос «ты умеешь X?»
в idle → уходит в буфер и получает «Накапливаю ▶️», а не ответ. Во время прогона вопрос →
held + «Принял ещё», но тоже без ответа. Это и есть «диалоги работают кривовато»: бот по
дефолту **копит, а не разговаривает**. (Дизайн «разговор/накопление» ты просил не менять —
поэтому выношу как факт, не как предложение переделки: сегодня разговор = только reply-to-bot.)
